# Codebase Review Findings — 2026-09-30

Review of the ~135 uncommitted files on `main` (as of commit `9e52dc0` plus working-tree changes).
Scope: find bugs and optimize **existing** features. No new features.

**Baseline at review time:** `pnpm --filter web test` → 72/72 pass · `pnpm --filter web lint` → clean · `pnpm --filter web build` → succeeds.
The green checks hide real problems, because several unit tests re-implement logic inline instead of importing the real modules (see #30).

All paths below are relative to `apps/web/` unless stated otherwise.

## 🔴 Critical — broken right now

1. **Service worker is a stale leftover and doesn't work.**
   `public/sw.js` + `public/workbox-1d075dc5.js` were generated by an old `next-pwa` build (build ID `FfJb1zZAfVvHbpzzb6nPF`), but `next-pwa` is no longer installed. The current build ID is different (e.g. `6VeShK6RRpkwZ6Fi3CkwY`), so the precached chunks 404 and install fails. It also calls `createPartialResponse` and `_ref`, which are never defined in the file. Result: the app can't load offline, so downloaded songs only play if the tab is already open.
   Also: `components/providers.tsx` registers the SW inside `window.addEventListener('load', …)` from a `useEffect` — if `load` already fired before hydration, registration never happens.

2. **Player state is written to localStorage ~4×/second.**
   Zustand `persist` writes after *every* `set()`, even when the `partialize`d slice is unchanged. `setProgress` is called on every `timeupdate`, so `stores/player.store.ts` serializes and writes `ytm-player` continuously during playback.

3. **Odia, Assamese and Urdu silently become Telugu.**
   `lib/security.ts:7` `ALLOWED_LANGUAGES` has 11 entries; `lib/languages.ts` offers 14. `sanitizeLanguage` falls back to `'telugu'` for the missing three.

4. **Sleep timer can *start* music instead of stopping it.**
   `components/AudioManager.tsx:185` calls `togglePlay()` when the timer ends — if the user already paused, playback starts. `sleepTimerEnd` is also persisted, so an expired timer fires again after reload.

5. **Queue drawer bugs** (`components/player/QueueDrawer.tsx`):
   - Shuffle on → wrong song highlighted as current (line 126 compares the shuffled list against `queue[qIndex]`, but `qIndex` indexes the *shuffled* list).
   - Drag-reorder sets `qIndex` to the drop position → "next" jumps to the wrong track; in shuffle mode it also turns shuffle off (lines 139–149).
   - Remove sets `qIndex` to the removed slot and turns shuffle off (lines 280–289).
   - The remove (✕) button is always invisible (`opacity: 0`, nothing ever changes it).

6. **Clicking a song in Up Next rebuilds/reshuffles the queue.**
   `components/player/ExpandedPlayer.tsx:410` and the drawer call `playSong(song, activeQueue, i)`, which calls `setQueue(…, keepShuffle=true)` → the whole upcoming order is reshuffled on every click. It should only jump to that index.

7. **A song with no audio URL spins forever.**
   If DES decryption returns `''`, `AudioManager.tsx:156` never sets `src` → `isLoading` stays `true`, no error event, no skip.

## 🟠 Functional bugs

8. **Like buttons don't update.** `SongCard`, `QuickPicksSection`, `ContextMenu`, `MiniPlayer` select `s.isLiked` (a stable function) → no re-render when `likedSongs` changes. MiniPlayer only looks right because it re-renders 4×/s.
9. **Mute forgets volume.** `toggleMute` sets `volume: 0` when muting; unmuting always restores `0.8` (`player.store.ts:94`).
10. **Video mode is broken.** Pausing audio fires `pause` → `isPlaying=false`, so the "advance progress during video" interval never runs (`ExpandedPlayer.tsx:60`). `next()`/`prev()` don't reset `mode` → next track's audio and video can play simultaneously. `togglePlay` (Space key / play button) resumes audio underneath the video.
11. **Visualizer is fake unless EQ is on, and wastes CPU.** Analyser is only created inside `setupEqualizer`. The rAF loop runs at 60fps forever (even paused) and allocates a `Uint8Array` + a gradient per bar per frame. Canvas isn't DPR-scaled.
12. **Controls silently change saved settings.** "Telugu"/"Hindi" mood chips permanently change the global language (`app/page.tsx:76`). "Start radio" permanently enables autoplay and restarts the current song from 0.
13. **Artist fallback searches by numeric ID.** `lib/saavn.ts:456` searches `artistId` (e.g. `"459320"`) in hard-coded Telugu → junk page.
14. **Autoplay radio runs dry.** `getSongRecommendations` always requests page 1 of the same queries; `appendSongs` dedups → soon nothing new. Artist-name search results aren't filtered to the artist.
15. **Queue grows forever.** Autoplay keeps appending; both `queue` and `shuffledQueue` are persisted to localStorage.

## 🟡 Performance

16. **Progress re-renders.** `AudioManager`, `MiniPlayer`, `LyricsPanel` subscribe to `progress`. `AudioManager` re-registers 7 MediaSession handlers + the keyboard listener ~4×/s; the whole MiniPlayer re-renders ~4×/s.
17. **Home page trips its own rate limit.** ~12 `/api/search` calls per visit, `staleTime: 0` + a new random page per mount → no cache reuse; changing a mood chip remounts/refetches every section (`key={id-mood}`). 5 home visits/min → 429s (limit 60/min).
18. **Search suggestions are expensive.** Header dropdown runs the full `searchSongs` (up to 4 upstream calls incl. Google suggest, 40 songs) to show 5; each keystroke-debounce counts against the rate limit.
19. **Serial upstream calls.** `searchSongs` makes primary → entity → suggestion searches in sequence (12s timeout each); lyrics make 3 sequential attempts (6s each, up to 18s). Also `fetchLyrics` does `return res.json()` without `await`, so JSON errors escape its `try`.
20. **Full-size art for tiny thumbnails.** `hiResImage` forces 500×500 and every `<Image>` is `unoptimized`; 40px thumbnails download full-size art. JioSaavn serves `-150x150`.
21. **Next track downloads twice.** Preload `<audio preload="auto">` downloads the whole next track at song start, the main element downloads it again, and `load()` at −5s re-fetches. Offline next-track blobs get a second, unused object URL.
22. **IndexedDB inefficiency.** `openDB()` opens a new connection per call, never cached/closed. `isSongDownloaded` loads the full record (with blob). Library page loads all records twice (`refreshDownloads` + `getOfflineStorageEstimate`).
23. **Render-blocking fonts.** Google Fonts stylesheet with Roboto 300 (unused) and 4 weights of Noto Sans Telugu for every user.
24. **Audio listeners re-attached constantly.** The listener effect depends on `volume`, `queue`, `qIndex`, `currentSong`… (`AudioManager.tsx:546`) → 8 listeners detached/attached on every volume-slider step and queue change.

## 🔵 Config, security, cleanup

25. **`vercel.json` likely breaks routing.** Rewrites every path to `/apps/web/$1`. The standard monorepo setup is Vercel "Root Directory" = `apps/web`. Needs verification on a preview deploy (owner decision).
26. **CSP.** `connect-src` still lists dead mirror `https://saavn.sumit.co`; `'unsafe-eval'` allowed in production.
27. **Rate limiter caveats (documented, no change).** In-memory per instance (weak on serverless); trusts first `x-forwarded-for` hop (fine behind Vercel, spoofable elsewhere).
28. **Duplication.** Two queue UIs (`QueueDrawer`, `UpNextPanel`) with diverging logic; 6 copies of the JioSaavn fetch boilerplate in `saavn.ts`; unused `getSong`; `AlbumCard`/`PlaylistCard` fetch outside React Query (no cache sharing with detail pages).
29. **Theme & leftovers.** `#1a1a1a` in `ExpandedPlayer.tsx`; `viewport.themeColor` fixed to `#0f0f0f` (dark status bar in light theme); manifest `<link>` + Apple meta tags duplicated in `app/layout.tsx` (already emitted by `metadata`); `next-pwa.d.ts` declares an uninstalled package; UTF-8 BOMs in `.eslintrc.json`, `components/home/SeenSongsContext.ts`, `.env.example`.
   (`app/global-error.tsx` hard-coded colors are intentional — it renders outside the root layout, so CSS variables are unavailable. The two `playwright.config.ts` files are both used — root runs from monorepo root, `apps/web` one from the package — keep both.)
30. **Store tests don't test the stores.** `lib/stores.test.mjs` and parts of `lib/offline-autoplay.test.mjs` copy logic into the test file; that's why #5/#6 weren't caught.
31. **Album page guesses metadata from the first song.** Title/artist/cover come from `songs[0]`, though `content.getAlbumDetails` already returns album-level `title`, `subtitle`, `image`, `year`.
